# Two years on 4.6.0: Cold Steel Mix, 24 November 2026

**The first run on Stellaris 4.6.0, with Stellar AI 0.21, UI Overhaul
Dynamic's 4.6 update and all 32 fixes, went well. Two years in a new galaxy
as the Commonwealth of Man logged 76 problems, 23 of them in play, and
nothing broke. Culture Worker jobs are filled, so Stellar AI no longer
breaks unity. The 1,708 ACoT entries are gone, as fix 44's change meant.
Two findings need a decision. 4.6 now logs a notice for every trait the
patch copies, and each names the mod's file. If 4.6 keeps the last copy of
a trait, as it does for buildings, fixes 18, 19, 27 and 42 do nothing. And
the planet view's city image looks wrong because Planetary Diversity -
Planet View replaces UI Overhaul Dynamic's whole planet view with a
reworked copy of the game's.**

- **Culture Workers work.** The save has a `culture_worker` job at 100 of
  100 workforce, and a `culture_worker_gestalt` at 100 of 100. No log entry
  names a job or a zone. The 4.6.0 update report's item 1 is settled.
- **Every trait the patch copies now logs a notice.** 16 notices, one for
  each of the patch's 16 trait copies, and none for any other trait. Each
  says `Object with key: <trait> already exists, using the one at` the
  mod's file. Up to 4.5.4, traits logged none. See
  [Traits in 4.6](#traits-in-46).
- **The city image is Planet View's.** Its `interface/planet_view.gui`
  wins over UI Overhaul Dynamic's. It's the game's 4.6 planet view with a
  taller planet picture: 570 pixels high, not 250. UI Overhaul Dynamic's
  own planet view, sprites and frames are built for its own layout. See
  [The planet view](#the-planet-view).
- **21 errors in play come from overlord holdings, all at one moment.**
  The game's own `15_overlord_holdings.txt`, and one holding each from
  Ascension Worlds and More Events Mod, switch to an `overlord` the
  player's empire doesn't have. Harmless. Likely the building list being
  opened. New with 4.6.
- **The patch held.** The build's 61 patch files match our folder byte for
  byte. No name the fixes deal with is logged as unknown.

## Traits in 4.6

**Up to 4.5.4 a trait copied in another file logged nothing. In 4.6 each
logs a notice.** It comes from `game_singleobjectdatabase.h:172`, the same
code that reports duplicate buildings, ship sizes and civics. There are 16,
for exactly the 16 traits the patch copies:

| Fix | Traits | Each notice names |
|---|---|---|
| 18 | 13, among them `trait_organic`, `trait_lithoid` and More Events Mod's three relic traits | Planetary Diversity's `02_species_traits_basic_characteristics.txt` and `04_species_traits.txt`, Ascension Worlds' copies, or More Events Mod's `mem_ancestors_grudge_traits.txt` |
| 19 | `trait_lithoid_budding` | `04_species_traits.txt` |
| 27 | `trait_aquatic` | `02_species_traits_basic_characteristics.txt` |
| 42 | `trait_cyborg_climate_adjustment_volcanic` | Planetary Diversity's `10_species_traits_cyborg.txt` |

The patch puts its trait copies in `!!_` files, which sort first, because
the [merge rules](../../../reference/patch-rules.md) say the first copy of a
trait wins. That row comes from Irony Mod Manager and was never checked in
game. The notice always names the copy read last. For buildings and ship
sizes the last copy wins, and the patch's notices name its own files. If
traits now load the same way, the mods' copies win, and fixes 18, 19, 27
and 42 change nothing in 4.6.

The log can't settle it. The notice may name the copy it keeps, or only the
file it was reading. Nothing in the save shows which definition of a trait
was used. 4.6's notes say nothing about traits loading differently.

## The planet view

**Planetary Diversity - Planet View's `interface/planet_view.gui` replaces
UI Overhaul Dynamic's whole planet view.** The build record lists UI
Overhaul Dynamic as the copy it overrides.

| | Planet View's copy | UI Overhaul Dynamic's copy |
|---|---|---|
| Based on | The game's 4.6 planet view, with its own changes marked `#V…` | UI Overhaul Dynamic's own layout, updated for 4.6 today |
| Planet picture | `planet_portrait_window` 840 × 570, picture moved down 140 pixels | Sized by UI Overhaul Dynamic's variables, scaled 1.112, with its own positions at each screen height |
| Background | `planet_view_bg` 850 × 783 | 100% × 100% |

Planet View exists only to show a larger planet picture. It ships the
`.gui`, its sprite file, stripes, frames and 17 star skies for planet
backgrounds. Its window is built for the game's interface, so with UI
Overhaul Dynamic the picture sits in a layout UI Overhaul Dynamic's frames
don't expect. This was likely so before today too: Planet View's file
replaced UI Overhaul Dynamic's 4.5 copy the same way. No fix or other mod
relies on Planet View.

## How it was worked out

- `error.log` read with our
  [error_log.py](../../../../src/stellaris_patcher/paradox/error_log.py),
  split by time with `game.log` and `time.log`, and grouped by source and
  text. Resource and override notices were counted apart.
- Each entry's file was traced through the build record of 19:43. Entries
  with no file were traced by the name or texture they quote, and checked
  against the game's own files.
- The build's patch files were compared with our folder. The build
  record's file times show UI Overhaul Dynamic's 19:23 files.
- The trait notices were matched, name by name, to the traits in the
  patch's four trait files.
- The game's, Planet View's and UI Overhaul Dynamic's `planet_view.gui`
  were compared, and UI Overhaul Dynamic's 4.5 sprite file with its 4.6 one.
- The ironman save was unpacked to a scratch folder, and its Culture
  Worker jobs and Caravaneer setting read.

# Two years on 4.5.3: Cold Steel Mix, 4 November 2026

**The first run on 4.5.3 logged nothing in play.** It was a new galaxy,
United Nations of Earth, from 2200.01.01 to 2202.02.03. Every one of its 100
problems is from loading or game start. 42 of them are the same loading
problems as earlier runs. 53 are new, and all come from 4.5.3's four-star
classes: the game's checks name `sc_quaternary_1` and
`sc_crisis_quaternary_1`, and Real Space's copy of the star class file
doesn't define them. They're harmless, and a small fix is proposed. Fix 42
worked at load: nothing logged an unknown Volcanic Climate Mods trait.
The patch was in the build and every copy it ships won. The user saw nothing
wrong.

- **The patch held.** Cold Steel built the playset at 21:59, two minutes
  after the patch was written. Its 73 patch files match our folder byte for
  byte, as do its 89 Stellar AI and 727 Real Space files. 40 duplicate
  object notices name the patch's files, the same as last run. None of the
  names the fixes removed are in the log.
- **Fix 17 isn't missed.** The save's Surveillance Supercomputer system has
  no `sealed_system` flag. It's Real Space 4.0.12's own copy now.
- **Fix 5 held on a Sol start.** Alpha Centauri, Sirius and Procyon spawned
  as Real Space's systems.
- **The four-star entries are load-time only.** See
  [Real Space and the four-star classes](#real-space-and-the-four-star-classes-53).
- **One new game start entry:** Real Space's Algorab system is too big. See
  [Game start](#game-start-2).

### Real Space and the four-star classes (53)

`Failed to deferred read key reference sc_quaternary_1 from database`, 27
times, and the same for `sc_crisis_quaternary_1`, 26 times, all at load.
4.5.3 adds both classes to the game's `00_star_classes.txt`, for its new
Stewart's Resolve system. Real Space 4.0 ships its own whole copy of that
file, which lacks them, as the
[4.5.3 update check](2026-11-04-4.5.3-update.md#stewarts-resolve) found.

| Where | Entries |
|---|---:|
| The game's `is_quaternary_star` (`common/scripted_triggers/00_scripted_triggers.txt` lines 1331–1332), through `is_multiple_star`, in its waystation modules, starbase buildings, three megastructures, astral actions, script values and seven event files | 52 |
| The game's Vacuum Flower relic (`common/relics/relics.txt` line 1469), which names `sc_quaternary_1` in a star class switch | 1 |

**They're harmless.** With no four-star class, `is_quaternary_star` is
false, which is right while no four-star system can spawn. So
`is_multiple_star` gives the same answer as the old binary and trinary
checks. They're only log noise, and they're now the biggest group of
problems.

## How it was worked out

- `error.log` was read with our
  [error_log.py](../../../../src/stellaris_patcher/paradox/error_log.py) and
  split by time with `game.log`: the game started at 22:03:11 and made the
  galaxy at 22:04:06. The last entry is at 22:04:09.
- Entries were grouped by source and text. Universal Resource Patch's
  `strategic_resources_gui_group.cpp` entries, and the duplicate object,
  entity, section template, event and variable notices, were counted apart.
- Cold Steel's build record (`builds/d8f5e037….json`) gave the build time,
  the patch's place last, and the source of each file. Each patch, Stellar AI
  and Real Space file in the built mod was compared with its source.
- Each duplicate object notice was matched to the files the patch ships.
- The raw log was searched for the names the fixes removed, and for fix 42's
  trait and variable.
- The ironman save was unpacked to a scratch folder. Its Sol system's lanes,
  its initializers and the Surveillance Supercomputer system's flags were
  read.
- The game's star classes were read to check that crisis classes have no
  `spawn_odds`.
